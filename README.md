# Grix

Grix 是 Agent 优先的即时通讯软件，支持 iOS、Android、macOS、Linux、Web 等平台。

Grix 让你像与人合作一样使用 Agent。

它把 Agent 放进联系人、会话、群组和工作流里。你可以像分配任务给同事一样 @ 一个 Agent，让它带着上下文工作、持续汇报进展、在需要时提问，并允许人随时打断、纠正或接管。

你不需要一开始就准备一整套 AI 供应商。只要你已经有 Claude、Codex、Kimi 等 14 个 Agent 中任意一个的可用订阅或本地接入，就可以先用 Grix 把它变成你的协作者、个人助理、客服或团队成员；以后需要更多角色时，再继续接入其他 Agent。

## 产品成熟度

Grix 不是概念原型，而是已经具备完整前后端产品形态的 Agent 协作系统，可以直接部署到生产环境使用。

**Grix 自身的项目开发、日常维护、问题排查、发布协调和文档整理，也是在 Grix 里完成的。** 这不是演示用例，而是长期真实使用的生产协作链路：用 Grix 开发和维护 Grix，持续验证它的稳定性、可靠性和团队协作能力。

- 后端服务、Flutter 客户端、Admin 管理后台、Agent 接入、群聊协作、权限控制、部署边界和发布接口已经打通。
- 仓库包含后端、前端、管理后台、协议文档、本地开发配置和不含凭据的部署示例；生产凭据、区域 overlay、云资源定义和发布台账由独立私有运维仓库维护。
- 通讯、群管理、权限授权、人类接管、Agent 接入和业务上下文沉淀都按生产系统设计。
- 长连接通讯、消息沉淀、权限边界、发布流程、部署配置和线上排障文档共同支撑稳定运行。
- 业务数据、历史对话、群聊上下文和权限关系沉淀在 Grix，不会被锁死在某一个模型会话里。
- 支持切换模型供应商或更换 Agent 接管同一业务，保证业务连续性。

## Grix 解决什么问题

多数 Agent 产品从模型能力出发：输入提示词，等待结果。

Grix 从人的协作方式出发：创建群、邀请成员、@ 负责人、共享上下文、观察过程、补充约束、处理异常、沉淀记录。它让 Agent 进入人的协作方式里，而不是要求人去适应复杂的自动化流程。

## 使用场景

### 个人：组织自己的 Agent 团队

个人开发者、独立产品人或小团队负责人，可以把 Grix 当成一支随时待命的 Agent 团队。

- 把 Codex、Claude、Kimi、Qwen、Cursor 等 Agent 设成不同角色：后端、前端、测试、文档、发布、客服、运维。
- 拉一个项目群，直接描述需求，让一个 Agent 拆解任务，再 @ 其他 Agent 分工。
- 从市场中的 115 个岗位复制出独立 Agent，把它们当成“一人公司”的员工使用。
- 授权某个 Agent 做个人助理，让它查看通讯录、检索对话、了解群聊、建群、拉人或推进群管理事项。
- 在手机上处理轻量开发协调，不必一直守在电脑前操作工具链。

这时 Grix 的价值不是替你多开几个聊天窗口，而是让你能像管理一个小团队一样管理一组 Agent。

### 企业：人和 Agent 在同一个群里协作

企业可以按项目、客户、产品线或职能拉群，把员工和 Agent 放在同一个上下文里。

- 单人与 Agent 协同开发：一个负责人调度多个 Agent，完成需求拆解、编码、测试、发布。
- 多人与 Agent 协同开发：产品、研发、测试、运维和多个 Agent 在同一项目群内协作。
- 客服或运营群接入 Agent：Agent 先处理重复问题、整理上下文，再把需要判断的事项交给人。
- 企业内部助理群：会议纪要、资料检索、任务跟进、报告生成由 Agent 承担，人负责确认和决策。
- 高风险操作保留审批：Agent 可以推进工作，但关键执行前仍由人确认。

协作过程沉淀在群消息里：谁提出了需求、哪个 Agent 接了任务、执行到哪一步、谁批准了关键操作，都可以被看见。

### 语音与客服：让 Agent 接起电话

接入语音模型后，Grix 里的 Agent 不只是在聊天框里回复文字，也可以成为能听、能说、能转交任务的语音协作者。

- 网站客服：Agent 接待访客咨询，支持文字和语音两种方式。
- 语音客服：用户像打电话一样提问，Agent 实时回答并记录上下文。
- 语音大脑：一个 Agent 作为语音入口，按你的语音指令唤醒开发、客服、文档、发布等其他 Agent。
- 主动跟进：授权某个 Agent 梳理业务进展，发现问题时主动向你发起语音通话。
- 人工接管：当 Agent 判断需要人处理时，把对话、摘要和关键上下文交给负责人。

## 核心能力

### Agent 像联系人一样存在

Agent 有身份、头像、权限、联系人关系和工作上下文。它可以进入私聊，也可以加入群聊；可以被 @、被分配任务、接收文件和后续指令；可以流式输出进展，而不是只在任务结束后返回结果。

### 群是人与 Agent 的工作房间

Grix 的群不是简单消息列表，而是多人和多 Agent 协作的工作空间。群管理关注的是：谁应该看到这件事、谁负责处理、谁需要确认、进展如何同步。

### 通讯就是 Agent 协调界面

Grix 用通讯能力组织 Agent：

- @ 路由注意力。
- 消息可见性控制上下文。
- 流式消息让长任务过程可观察。
- 撤回、停止、接管和干预流程保留人的控制权。
- 跨会话和连接器消息让 Agent 参与更广的业务场景。

### 业务不绑定单一模型或供应商

有了 Grix，你不需要把业务绑定在某一个大模型、某一个 Agent 或某一家供应商上。

联系人、群聊、历史对话、任务上下文、权限关系和协作记录都沉淀在 Grix 里。你可以随时接入新的模型供应商或新的 Agent，让它接管之前的业务，沿着已有上下文继续往下做。

### Admin 后台管理

Grix 不只是前台聊天产品，也包含完整的 Admin 后台和 `/admin/api` 管理接口，用于支撑生产环境运营。

- Flutter 跨平台 Admin App 覆盖 Web、桌面和移动端，生产环境可直接连接正式 API。
- Admin API 使用 Bearer Token 认证和 RBAC 权限模型，每个管理模块都有独立权限 key。
- 支持管理员和角色管理、用户管理、举报处理、内容审查、系统设置和 Feature Gates。
- 支持 App 版本发布、Connector 升级、虾蛋市场、链接黑名单、访客封禁、推送和网关相关配置管理。
- 管理后台与业务服务共用稳定后端能力，让运营、风控、发布、灰度和安全配置可以集中处理。

## 安全与控制

Grix 的安全设计不是把 Agent 关在黑盒里，而是让 Agent 的工作始终处在主人可见、可控、可授权的协作关系中。

- **角色拆分**：即使底层使用同一个 Claude、Codex 或 Kimi，也可以拆成后端、前端、测试、文档、发布等不同角色，每个角色有独立上下文、职责、权限和模型参数。
- **主人可见**：Agent 在群里的对话、任务进展、协作过程和关键操作，主人都能看到。
- **随时接管**：主人可以打断输出、补充约束、调整模型和参数、暂停任务、转交任务或直接接管。
- **授权访问**：任何人要与你的 Agent 对话，都必须经过授权；Agent 查看通讯录、对话记录、群聊信息，或代表你建群、拉人、管理群，也必须在授权范围内进行。
- **群内权限**：每个 Agent 的主人可以设置谁能与它对话、谁不能对话、它能看到哪些上下文、是否可以参与某个群或某类任务。
- **Agent 间对话可见**：Agent 与 Agent 协作时，主人必须能看到对话内容，并且需要有授权关系，不能在用户看不见的后台私下串联。

## 技术与仓库
